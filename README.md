樣鞋房雙系統管理帳本 - 技術維護手冊

恭喜！您的雲端同步系統已正式上線。這份手冊記錄了系統的核心設定，供未來維護參考。

🛠 今天的技術戰果 (Key Learnings)

1. 雲端大門：Firebase Authentication

功能：確保只有「被授權的網頁」能進入系統。

關鍵開關：必須在 Firebase Console 啟用 「匿名 (Anonymous)」 登入。

網域守衛：在「授權網域」中加入了 shuchia.github.io，這防止了別人隨便拷貝您的代碼去連您的資料庫。

2. 鑰匙權限：Google Cloud API Key

服務關聯：API Key 不是萬能鑰匙，它必須關聯 Identity Toolkit API 才能處理登入。

限制設定：我們學會了如何在 Google Cloud Console 設定「網站限制」與「API 限制」。

重要經驗：Google 的伺服器更新設定需要 5-15 分鐘，這就是為什麼有時候「設定對了但還沒生效」的原因。

3. 保險庫規則：Firestore Security Rules

路徑結構：資料儲存在 /artifacts/shoe-factory-manager-ledger/ 下。

安全防禦：規則設定為 if request.auth != null，代表只有通過驗證的連線（即您的 GitHub 網頁）能改動資料。

📋 系統日常操作提示

💡 快速操作手勢

左鍵點兩下 (Double Click)：對著型號點兩下，系統會自動判斷這雙鞋是「要歸還」還是「要再次借出」，並自動帶入品牌與型號，省去手打時間。

📱 多裝置同步

您可以直接用手機瀏覽器打開同一個網址。

手機版優勢：在倉庫收鞋時，直接拿手機點兩下就能完成「簽收結案」。

📊 資料備份

系統提供 「匯出報表」 功能。建議每週點擊一次，下載 CSV 存檔在電腦裡作為歷史紀錄備份。

🆘 未來遇到連線失敗怎麼辦？

檢查網路：確認是否連上 Internet。

等待更新：如果您動過 GitHub 代碼，GitHub Pages 通常需要 1-2 分鐘才會更新。

瀏覽器快取：如果設定改了沒反應，嘗試用「無痕模式」打開網址測試。
